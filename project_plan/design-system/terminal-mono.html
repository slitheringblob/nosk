01/principles

Seven rules everything follows

monospace

One typeface everywhere

UI, content and code share one face. Hierarchy comes from size, weight, case and colour.

shape

Square and flat

Radius is 0. Hairlines separate surfaces; only floating layers cast shadows.

accent

One accent, sparingly

Amber marks the primary action, the selection, focus and live state. If everything is amber, nothing is.

hierarchy

Quiet chrome, loud content

Controls are small, dim and labelled in caps; the user's content is larger and brighter.

surfaces

Translucent layers

Fills are low-alpha tints of the text colour, so they stack and adapt to both themes.

controls

Reveal on intent

Secondary controls appear on hover and focus, and stay out of the way otherwise.

voice

Terminal garnish

~/path, $ sign in and 01/ indices decorate. They never replace clear labels.

Using the accent

amber is for
  • The one primary button per view
  • Active nav item, tab, selected row
  • Focus rings, text selection, the cursor
  • Progress and live indicators
not for
  • Body links (use blue)
  • Decorative borders
  • Several buttons on one screen
  • Large backgrounds (use the wash)

Status mapping: info blue, success green, warning amber, error rose, note violet. Tinted panels mix 7% of the colour into transparent and add a 2px left border in the solid colour.

05/shape & elevation

Edges do the work shadows usually do

Radius is 0 everywhere. Emphasis comes from a 2px edge in amber or a status colour. Only menus, modals, toasts and palettes float.

default1px --bdr hairline
selectedamber wash + 2px left edge
active tab2px bottom edge
empty / drop1px dashed --bdr-hi
floating--shadow-float on --panel

Sticky chrome is translucent: background: var(--nav-bg); backdrop-filter: blur(14px) saturate(140%). Modal backdrops use --scrim with a 3px blur.

06/atmosphere

Depth without noise

You're looking at it: two fixed layers behind the page. A 32px grid in --grid, faded out with a radial mask, and two blurred glows, amber top-left and blue top-right, at 70% opacity (50% in light).

One signature motif: the blinking block cursor, amber, 0.5em × 0.82em, 1.05s step-end. Use it after the wordmark and the hero headline, never in body text. Keep atmosphere at z-index: 0 with pointer-events: none.

# Only edits to the same entity from another device conflict.
async def concurrent_change(session, actor, entity_id, base_version):
    return await session.scalar(
        select(SyncOperation).where(
            SyncOperation.entity_id == entity_id,
            SyncOperation.page_version > base_version,
            SyncOperation.device_id != actor.device_id,
        ).limit(1)
    )  # → "version_mismatch"

09/accessibility

Readable, reachable, honest

focus

Always visible

1px amber outline, 2px offset, on :focus-visible. Never remove it without a replacement.

state

Never colour alone

A status dot always has a label; a read-only page shows a badge, not just a grey title.

keyboard

Every action, every key

Arrows, Enter and Esc in lists and menus. Shortcuts appear as keycaps in menus.

hover

Hover also means focus

Anything revealed on hover also shows on :focus-within, and is always reachable on touch.

targets

Big enough to hit

At least 28px on desktop, 40px preferred on touch.

semantics

Name the controls

aria-label on icon buttons, role="dialog" on modals, aria-live on status.

10/theming

Dark first, light on request, no flash

Store the preference as system | dark | light, resolve system with prefers-color-scheme, set color-scheme in each theme block, and apply data-theme before first paint.

<head>
<script>
  (function () {
    var pref = 'system';
    try { pref = localStorage.getItem('theme') || 'system'; } catch (e) {}
    var dark = matchMedia('(prefers-color-scheme: dark)').matches;
    document.documentElement.dataset.theme = pref === 'system' ? (dark ? 'dark' : 'light') : pref;
  })();
</script>
<meta name="theme-color" content="#06070b">

12/do & don't

Guardrails

do
  • One typeface; hierarchy from size, weight, case
  • Hairlines and translucent fills
  • One amber primary per view
  • Square corners
  • Dim, small chrome; bright, larger content
  • Status as colour and words
  • Tokens only in component CSS
  • Terminal details as accents
don't
  • Mix in a sans-serif "for readability"
  • Drop shadows on cards
  • Amber borders on everything
  • "Just a little" 4px radius
  • Equal weight everywhere
  • A red dot as the only error signal
  • Raw hex values in components
  • ASCII art, scanlines, green-on-black pastiche
